# 구현 순서 및 완료 기준

## 1. 데이터·권한·API 계약 확정 (현재 로컬 구현)
고령자 한 명당 Care Group, owner/caregiver/elder 역할, 그룹 접근 범위를 먼저 고정합니다. 현재 담당자만 일정 승인과 교대를 수행합니다. 프론트·AI 담당자에게 API.md를 공유해 필드와 오류 계약을 확정하세요.

완료 기준: 다른 가족 조회 차단, 고령자의 보호자 작업 차단, 작성자 위조 차단 테스트 통과.

## 2. Care Timeline (현재 로컬 구현)
병원·복약·식사·귀가·센터·특이사항 등록과 시간순 조회를 먼저 프론트에 연결합니다. ISO 시간대를 필수로 받고 저장은 UTC, 화면 표시는 한국 시간으로 통일합니다.

완료 기준: 기록 등록 후 재조회·재시작 복원, 작성자와 원문 출처 확인.

## 3. 일정 및 승인 (현재 로컬 구현)
등록 → 변경/취소 요청 → 담당 보호자 승인/거절 흐름을 연결합니다. 요청 생성 시 일정은 유지되고 승인 시에만 바뀝니다. 중복 처리와 이전 버전 승인은 차단합니다.

완료 기준: 고령자 요청, 보호자 승인, 거절, 중복 요청, 완료된 일정에 대한 승인 테스트 통과.

## 4. 보호자 교대 및 대시보드 (백엔드 로컬 구현)
다음 담당자 지정, 명시적 교대, 담당 이력을 연결합니다. 교대 시 미처리 요청을 새 담당자에게 이관합니다. 프론트에서 현재/다음 담당자, 오늘 일정, 최근 기록, 대기 요청을 표시합니다. 주간 자동 교대와 미래 기간별 배정은 후속 확장입니다.

## 5. AWS 운영 기반 (미구현)
Cognito JWT 인증에서 sub를 사용자 ID로 전달하고 가입/초대 흐름을 구현합니다. 현재 파일 저장소는 Lambda에서 사용할 수 없으므로 DynamoDB 저장소로 교체합니다. 그룹 파티션과 시간 정렬 키를 설계하고 Query 페이지네이션, 조건부 쓰기와 TransactWriteItems로 승인·일정·이력 동시 변경을 보장합니다. API Gateway/Lambda, 최소 IAM, 암호화, 백업, 로그 개인정보 제거, 허용된 프론트 도메인 CORS를 IaC로 구성합니다.

완료 기준: 별도 테스트 AWS 계정에서 가족 간 접근 제한, 동시 승인 경쟁, 저장 장애 롤백, 재배포 후 유지, 인증 만료 통합 테스트 통과. 실제 배포 전 리전·계정·비용 범위를 확정합니다.

## 6. Bedrock Care Handoff (현재 원문 분류 대체 구현)
5단계 이후 최근 기록과 예정 일정만 모델에 전달합니다. 건강/생활/일정/확인사항 JSON 스키마와 근거 eventId를 검증하고 기록에 없는 진단·복약 변경을 생성하지 않도록 제한합니다. 기록 본문은 명령이 아닌 데이터로 취급합니다. 모델 장애 시 현재 extractive 응답으로 대체하고 모드를 명시합니다. 모델 선택과 실제 SDK 연결은 AWS 환경 확정 후 진행합니다.

완료 기준: 근거 없는 내용, 기록 안의 지시문, 빈 기록, 모델 타임아웃 평가 통과.

## 7. 음성·알림 및 생활 상태 확장 (미구현)
텍스트 질문 API에 Transcribe/Polly를 연결합니다. 자연어 시간 범위와 의도 파싱을 추가하고 일정 선택 후 승인 요청으로 연결합니다. EventBridge/SNS 등으로 보호자 알림을 연결합니다. 위치·생활 패턴 감지는 수집 동의, 관찰 기준, 알림 중복 방지 정책 확정 후 별도 구현합니다.

추천 시작점: 지금은 로컬 API를 실행하고 프론트에서 ‘그룹 만들기 → 기록 남기기 → 일정 등록 → 취소 요청 → 승인 → 교대 → 인수인계 보기’ 한 흐름을 먼저 완성하세요. 이후 AWS 운영 기반과 생성형 AI를 차례로 연결하면 됩니다.
